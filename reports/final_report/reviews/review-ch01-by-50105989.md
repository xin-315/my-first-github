# Chapter Review: Chapter 1 Introduction
**Reviewer:** 50105989 (UI/UX Designer & Frontend Engineer)
**Review Date:** 2026-11-04
**Review Standard:** JC2001 Software Engineering Technical Report Specification

## Review Comments
1.  **Requirement traceability**
    It is recommended to append the corresponding requirement ID from the Requirements Traceability Matrix at the beginning of each core implementation section. This will explicitly demonstrate the requirement-driven implementation logic, which is a core evaluation point of the software engineering course and aligns with the group's full-report traceability specification.

2.  **Academic citation support**
    Part of the theoretical and methodological descriptions currently lack academic citation support. It is suggested to supplement Harvard-style references for core theoretical foundations — for example, corresponding software engineering methodology, domain pedagogy or technical framework literature — to comply with academic norms and support the full report's requirement of ≥25 references.

3.  **Figure richness and standardisation**
    The current number of figures in this chapter is slightly below the average allocation. It is recommended to add 1–2 supplementary diagrams, such as implementation screenshots, architecture layering or workflow diagrams, to help meet the full report's target of ≥18 figures. Meanwhile, please unify the figure caption format with "Figure X.X: Description" to keep consistent with the full-report List of Figures.

4.  **Validation and risk consideration**
    It is recommended to add a short subsection explaining the verification method or risk mitigation strategy of this module. For example, test coverage, graceful degradation mechanism or boundary-case handling. This corresponds to the software quality assurance and risk management content in the course, and will significantly enrich the depth of the chapter.

5.  **Terminology consistency**
    There are slight inconsistencies in the naming of several key nouns compared with the RTM and project proposal. It is recommended to unify the terminology of core concepts, function names and requirement labels, so as to avoid terminology conflicts during the final consolidation of the full report.

6.  **Structure and page count balance**
    The length distribution of subsections is slightly uneven: the introductory part is relatively long while the core implementation part is slightly thin. It is suggested to adjust the content proportion, focus on the implementation details and technical highlights, and control the total page count within the target range.
